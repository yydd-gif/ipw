## 一、这个包是什么

一套**面向施工方**的完整实现方案：把「建一个工程 = 建一个文件夹；一键成册 = 套完 37 份模板并填好 39 个字段；打完印标记状态；整册导出 PDF」这件事，拆成了可照着实施、可验收的设计与契约。

本包**不含可执行成品**，含的是**方案 + 契约 + 资产 + 工具**。

| 项 | 值 |
|---|---|
| 交付形态 | 设计文档 + 契约表 + 模板资产 + 体检工具 + AI 组合包源码 |
| 目标产品形态 | 对标「筑业云资料」：Ribbon + 左侧三页签树 + 右侧编辑区 |
| 技术底座 | DeepSeek Harness（dsh）+ Electron 壳 + `@genoffice/docx-engine` 编辑内核 |
| 交付口径 | **施工方实现**；本包内的 DoD 均为**可验收硬标准** |

## 五、3 条红线（破了就白干）

1. **不碰 `07_模板资产/` 下任何 docx** —— 37 份 + 171 占位符是冻结资产。引擎只读，输出到工程目录，**永不回写**。
2. **占位符替换必须在「同段落内跨 run 合并」后再落笔** —— 实测 6 份模板 / 14 处被 Word 拆散在多个 run，逐 `<w:t>` 替换会**静默漏填**且 Word 里看不出来。
3. **docx 一律部件级操作**（zip 读入 → 改 XML → 原样写回），**不用 python-docx / docxtpl / docxtemplater 重排**。

> 完整 12 条见 `00_包说明.md`「约定（红线）」。

## 八、怎么自检这个包

```bash
# 1) 模板资产生成完整性（37 份现役 + 37 份备份，SHA256 校验）
python 03_工具脚本/backup_templates.py --verify-only

# 2) 源 ↔ 冻结备份 部件级 / 文本级保真比对（V3 指定工具）
python 03_工具脚本/diff_parts.py

# 3) 占位符 ↔ 字段字典 对账（A~F 六类）
python 03_工具脚本/diff_mapping.py

# 4) 排版体检（页边距 / 页眉页脚 / 字体 / 横向页，val-aware）
python 03_工具脚本/audit_typography.py

# 5) 模板位置定位（导出 段N / 表M行R列C）
python 03_工具脚本/locate_docx.py
```

> **运行环境**：Python 3.13（仅标准库，**不依赖 lxml / python-docx**）。
