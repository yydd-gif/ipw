## 1. 这个项目是什么（30 秒版）

给一个工程项目做的**验收资料自动生成与管理系统**。Windows 桌面软件，对标「筑业云资料」的形态：

**建一个工程 = 建一个文件夹；点一次「一键成册」= 套完 37 份模板并填好 39 个字段；打完印标记状态；最后整册导出 PDF 归档。**

**三条技术主线（记住这三条，其余都是细节）：**

| 主线 | 一句话 | 落在哪 |
|---|---|---|
| **确定性内核** | 7 个 Python 引擎，不联网、不调模型，输入固定输出唯一 | `assets/engine/*.py` |
| **AI 层** | dsh（DeepSeek Harness）当后端，一行源码不改，只挂自己的组合包 | `dsh-yanshou-docs` 组合包 |
| **桌面壳** | Electron，自建界面与编辑内核 | 主程序 |

**当前进度：设计完成 ~88%，代码只完成了填充引擎原型（已验证 37 份 / 171 处占位符 / 100% 命中）。** 其余全部待建。

## 3. 三条不能碰的红线（碰一条返工）

| # | 红线 | 怎么自证 |
|---|---|---|
| 1 | **绝不写入 `assets/templates/**`**（37 份模板是冻结资产） | 写个测试试着往模板目录写文件，必须抛 `TemplateProtectionError` |
| 2 | **docx 一律部件级操作**：zip 读入 → 改 XML → 按原 `infolist()` 顺序写回。**不用 python-docx 打开再保存** | 处理后的文档跑 `03_工具脚本/diff_parts.py`：只有目标部件变，媒体逐字节一致 |
| 3 | **缺值保留 `{{key}}` 原样**，绝不填空字符串或空格 | 人为留一个空字段，检查输出文档里 `{{key}}` 还在 |

**另外两条同等重要：**
- **日期一律不自动填**（12 个日期字段是封闭集，引擎加载期就会拒绝相关规则）
- **编号在目录项内不重排**（删掉 `02`，`03` 仍是 `03` —— 这是已打印纸质件的命根子）

## 4. 环境准备

### 4.1 版本要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Node.js | **≥ 22.19** | dsh 与 genoffice 都要求（实测 dsh 为 `0.1.5-rc.x`） |
| pnpm | ≥ 10 | dsh 插件安装依赖它 |
| Python | **3.13.x**（建议 3.13.12） | 引擎运行时；交付时需内嵌到 `assets/runtime/` |
| lxml | 最新 | **引擎唯一的重依赖**，含原生扩展 —— **打包是坑，提前验证** |

### 4.2 装依赖

```sh
# 桌面壳 + 编辑内核
pnpm install

# AI 层组合包
cd dsh-yanshou-docs && pnpm install && pnpm run build && pnpm pack
dsh plugin --profile yanshou add ./dsh-yanshou-docs-<version>.tgz
dsh --profile yanshou --dump-config     # 应看到 "# == dsh-yanshou-docs" 层

# Python 引擎依赖（建议独立 venv）
python -m venv .venv && .venv/Scripts/pip install lxml pyyaml pypdf
```

### 4.3 环境变量

| 变量 | 用途 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY`（或所选厂商对应变量） | 模型调用 | **走环境变量，不写配置文件**（红线） |
| `DSH_HOME` | dsh 配置根 | 测试时用隔离目录，别污染本机 |

## 9. 已知坑清单（前人踩过，别重踩）

| # | 坑 | 对策 |
|---|---|---|
| 1 | **Word 会把 `{{projectName}}` 拆到多个 run 里**，逐 run 查找必然漏。**实测本包已有 6 份模板 / 14 处 / 12 个字段中招**（二-4×4 / 二-10×5 / 二-8×1 / 六-6×2 / 六-9×1 / 七-1×1），其中最要命的 `二-10 施工日志` 是"施工日志驱动自动生成"的载体。拆散形态如 `<w:t>{{</w:t><w:t>weather</w:t><w:t>}}</w:t>`，**Word 里显示完全正常，肉眼查不出来** | **跨 run 替换**：拼出段落全文 → 记录每个 run 的偏移 → 定位区间 → 覆盖起始 run、清空跨越的其余 run 文本。**开工前先读 `02_引擎源码/fill_engine.py` 的 `splice()`（已实现，别改坏）**。回归用例用 `03_工具脚本/diff_mapping.py` 的 **F 检查**守住。<br>⚠ 反过来说：`{{` 左括号本身**从未被切开**（实测节点级 171 == 段落级 171），所以**逐节点扫 `{{` 的残留检测不会漏检**，`scan_residual()` 不必改 |
| 2 | 表格行数不固定，不能"填空"思维 | **行克隆**：读首个数据行作模板行，deepcopy XML 节点插入 |
| 3 | 日期位置必须原样跳过 | 全角空格排版（`年　　月　　日`）**整段保持**，不替换也不清空格 |
| 4 | 正则量词必须用 `{2,}` 不能用 `{2}` | 中文占位有 `XX`/`XXX`/`XXXX` 多种长度 |
| 5 | 同段落多条替换规则区间不能重叠 | 相邻位置**合并成一条正则** |
| 6 | 模板里的"提示文字"不是占位符 | 空格/下划线紧邻"签章/签字/盖章"字样的，属人工区，不注入 |
| 7 | 改同一个文件禁止并行编辑 | 读-改-写竞态会互相覆盖；**串行提交，改完复核** |
| 8 | docx 重新保存会剥离 zip 目录条目（`word/` 等） | 属正常，但必须确认**实际部件无缺失、图片逐字节一致** |
| 9 | 字典"启用字段"与模板"实际使用 key"必须严格相等 | 每次改字典或模板后用 `field_usage_diff.py` 对账 |
| 10 | `link:` 本地路径安装插件在 Windows 上得到**空目录**，且报错信息误导 | **只用 tarball**（`pnpm pack` → `.tgz`）。碰到"declares no dsh.bundle"警告，先去 `node_modules/<pkg>/` 看文件在不在 |
| 11 | **PyMuPDF 等一批 PDF 库是 AGPL-3.0** | 用 **`pypdf`**；AGPL 组件一律不引入（要留住"将来给同行用"的可能） |
| 12 | 不要用 python-docx 重排文档 | 会丢样式、改媒体。走部件级操作 |
| 13 | **"模板里有脏数据/漏检"这类结论极易假阳性** —— 本包连续踩过三次：正则剥 `<...>` 把 XML 属性数值泄漏成正文（误报"数字垃圾"）；把所有段落拼成一整串再数 `{{`，段落接缝凑出假 `{{`（误报"残留扫描漏检 11 处"）；正则分词器把自闭合标签解析错（漏解析整个分册） | **结论必须落到 `w:t` 文本节点 + 逐段落口径**，并用**至少 2 种独立方法交叉验证**再上报。已把 ET 口径固化进 `locate_docx.py` / `diff_mapping.py` / `audit_typography.py` |
| 14 | **读 `w:t` 前必须先删 `mc:Fallback` 子树** —— OOXML 的 `mc:AlternateContent` 会同时存 DrawingML（Choice）和 VML（Fallback）两份，**同一段文字出现两次** | 踩过两次：页脚「第 4 页第 4 页」实为「第 4 页」；`2828` 实为 `28`。**看到"文字莫名重复"或"数字翻倍"先查这个**。`audit_typography.py` 里的 `drop_fallback()` 可直接复用 |
| 15 | **页码域（PAGE / NUMPAGES）的缓存值也是 `w:t`** —— 页脚里那串数字不是手打死字，是域的上次计算结果 | 判"页码写死了"之前，先查同部件的 `w:instrText` 有没有 ` PAGE `。**查域要连 header/footer 部件一起扫**，不能只扫 `document.xml` |
| 16 | **段前分页（`w:pageBreakBefore`）会失控** —— 复制粘贴 / 格式刷会把它带到每一段上，导致**每段强制新起一页** | 判据看"占比"不看绝对数。体检用 `audit_typography.py`，修复用 `fix_typography.py`。**⚠ 但下一条优先级更高** |
| 18 | **"备份校验通过"≠"源没被改过"** —— 只比对「备份 vs 清单记录」只能证明**副本没被改坏**；源在备份之后被谁（人或 Word 另存）动过，**查不出来**。我第一次做"零改动复核"就因此报出假结论「37 份全部一致」，实际差 1 份 | `backup_templates.py --verify-only` 现已含两段：**A 副本完整性** + **B 源↔备份同步性**（漂移时打源/备双侧 mtime + 字节数，并 `exit 1`）。**B 段不能省。** 发现漂移先用 `diff_parts.py` 做部件级/文本级比对定性（Word 另存常是"字节变、内容不变"），再决定是**覆盖备份**还是**还原源** |
| 19 | ★★ **"路径写死"的体检脚本会静默假 pass** ★★ —— `diff_parts.py` 原版 `ROOT = r'F:\验收资料编辑软件'`（另一台机器）→ `os.walk` 扫到 **0 个文件**，却照样打印「对比 0 个模板；部件有差异的: 0」**并正常退出**。而它是本包 **V3 保真验证的指定工具** → 施工方按流程跑会拿到一份"通过"的假报告 | **已重写**（CR-009）：根路径从 `__file__` 推导；输出**份数**（0 份要显式报错而非静默通过）；部件级 + 文本级双判；三态判定 + 退出码。**通用纪律：任何体检/校验脚本，第一条输出必须是"我扫了多少个对象"，为 0 就直接非 0 退出。** 另：`diff_parts.py` 现支持 `diff_parts.py <A> <B>` 单比两份 |
