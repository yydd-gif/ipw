## 0. 施工方先看这三条

1. **本文定义的字段名、键名、参数名一个字都不能改**（包括大小写与下划线前缀）。契约冻结后要改走变更记录。

- `_` 开头目录为软件自留区；引擎只允许写 `--out` 指定目录

### 2.2 `_fieldSources`（值来源标记）

每个项目级字段可带一条来源记录，用于界面角标与冲突提示。

```jsonc
"_fieldSources": {
  "projectName": { "source": "S1", "ruleId": "proj.projectName", "at": "2026-09-16T09:30:00", "by": "manual" },
  "buildSite":   { "source": "S2", "ruleId": "compose.buildSite", "at": "2026-09-16T09:30:00", "by": "engine" }
}
```

| 字段 | 类型 | 取值 |
|---|---|---|
| `source` | string | `S0`–`S6`（定义见设计文档 §4.2） |
| `ruleId` | string | 产生该值的规则 id；人工填写时为空串 |
| `at` | string | ISO 8601 本地时间 |
| `by` | string | `manual` / `engine` / `ai` |

**实现要求**：字段无 `_fieldSources` 记录时，一律按 `S1 / manual` 处理（向后兼容）。

### 2.3 `_documents`（文档级覆盖）

键 = **文档相对路径**（相对工程根，`/` 分隔，**不带工程目录名前缀**），值 = 该文档的字段覆盖。

```jsonc
"_documents": {
  "二、过程分册/1、开工报审表/YY123-KGBSB-01_开工报审表.docx": {
    "docNo": "YY123-KGBSB-01",
    "handoverPlace": "岳阳市财政局档案室"
  }
}
```

| 约束 | 说明 |
|---|---|
| 键格式 | `{分册}/{目录项文件夹}/{文档文件名}`，全 `\` 转 `/`，**不带前导斜杠** |
| 值 | `{字段key: 值}`，只要字符串/数字，不要嵌套 |
| 空值处理 | 值为 `null` 或 `""` 时视为"无覆盖"，不参与决议链 |
| 清理 | 文档被删除进回收站时，其覆盖条目**保留**（还原时要用）；彻底删除时才清理 |

### 2.4 `_assets`（子表数据源）

**v2.0 新增。** 存放需要跨文档复用、但又不属于 39 字段的结构化数据（目前只有设备/软件台账）。

```jsonc
"_assets": {
  "devices": [                                    // ← 对应 tables.deviceList
    { "序号": 1, "名称": "核心交换机", "主要性能指标": "24口千兆",
      "品牌及型号": "H3C S5130", "所属系统及部署位置": "机房A柜",
      "单价（万元）": "0.85", "数量": 2, "总价（万元）": "1.70", "说明": "" }
  ],
  "softwares": [ ]                                // ← 对应 tables.softwareList
}
```

| 约束 | 说明 |
|---|---|
| 列名 | **必须与 `字段字典.json` → `tables[].columns` 完全一致**（含全角括号），否则子表引擎不认 |
| 列序 | 与 `columns` 一致；缺列可留 `""`，**不得新增列** |
| 数值列 | 以**字符串**存储（避免浮点误差），由引擎按 `tables[].columns` 类型解析 |
| 空数组 | 合法，表示该子表无数据（引擎按模板静态表原样保留，不删行） |

### 2.5 `_numbering`（编号池）

```jsonc
"_numbering": {
  "二-01": {                                   // 键 = itemId（分册序号-目录项序号）
    "prefix": "YY123-KGBSB",                   // 合同编号 + 表名缩写；无合同编号时只有缩写
    "digits": 2,                               // 流水号位数（2 或 3）
    "allocated": [                             // 在册：永久绑定
      { "docId": "D-KGBSB-01", "no": "YY123-KGBSB-01", "at": "2026-09-16" }
    ],
    "released": ["YY123-KGBSB-02"],            // 已释放，可复用（取序号最小者）
    "max": 2                                   // 历史最大序号，保证「不重排」
  }
}
```

**三个不变量（必须用单测锁死）：**
1. `allocate` 取 `released` 中序号最小者；`released` 空则 `max += 1`
2. `release` 时若序号 == `max`，则 `max -= 1`；否则进 `released`（**中间号留坑，不重排**）
3. `restore` 从 `released` 移除并绑回原 `docId`；**不重新分配**

### 2.6 `_printStates`（打印状态）

```jsonc
"_printStates": {
  "D-KGBSB-01": { "printed": true, "printedAt": "2026-09-16T15:04:00", "times": 2 }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `printed` | bool | 是否已打印过 |
| `printedAt` | string | 最近一次打印时间（ISO 8601） |
| `times` | number | 累计打印次数 |

**注意**：键是 `docId`（不是 `docNo`，也不是路径）。打印状态与文档内容解耦。

### 2.7 `_catalogSnapshot`（清单快照）

```jsonc
"_catalogSnapshot": {
  "version": "1.0",
  "parsedAt": "2026-09-16",
  "sourceHash": "sha256:…",          // 源 `软件目录.docx` 的哈希，用于检测清单是否变更
  "items": [
    {
      "itemId": "二-01",             // 稳定 ID = 分册中文序号 + "-" + 两位目录项序号
      "volume": "二、过程分册",
      "volumeSeq": 2,                // 分册序号（1–8，数字）
      "seq": 1,                      // 分册内序号
      "name": "开工报审表",
      "relPath": "二、过程分册/1、开工报审表",
      "hasTemplate": true,
      "dataType": "工程建设类",       // 工程建设类 / 政务信息化类 / 上传附件
      "importance": "普通项",         // 重要项 / 普通项 / 一般项（软件目录.docx 元数据，不成册依据）
      "inclusion": "optional",       // required / optional（表名缩写字典「收录」列）
      "required": false,             // inclusion==required：生成必选会建表；可选默认无实例
      "templateFile": "1、开工报审表.docx",
      "abbr": "KGBSB",
      "docDigits": 2,
      "numbered": true
    }
  ]
}
```

| 约束 | 说明 |
|---|---|
| `itemId` | **生成后永不变**。编号池、回收站、打印状态都按它索引 |
| `volumeSeq` | 1=一、依据分册 … 8=八、封面页（用于整册排序与卷册清单补齐） |
| `hasTemplate=false` | `templateFile` 为空串 |
| `numbered` | 仅 9 项为 `true`（见 `表名缩写字典.csv` 的「启用编号」列） |
| `required` | 以 `表名缩写字典.csv` 的「收录」列（`inclusion`）为准，**不**从 重要/普通/一般 推导。首版名册：全部上传项 + 二-01～二-05 = optional；其余有模板项 = required。生成必选（`--item all`）只生成 `required=true` 以及**已经有实例**的可选行 |

### 2.8 `_docs`（文档实例清单）

```jsonc
"_docs": {
  "D-KGBSB-01": {                                       // 键 = docId
    "itemId": "二-01",
    "relPath": "二、过程分册/1、开工报审表/YY123-KGBSB-01_开工报审表.docx",
    "docNo": "YY123-KGBSB-01",
    "fillState": "complete",                            // empty / draft / complete / error
    "createdAt": "2026-09-16T09:30:00",
    "updatedAt": "2026-09-16T09:30:00",
    "anchors": ["projectName", "contractNo", "docNo"]   // 该文档里带锚点的字段（§5）
  }
}
```

**`docId` 生成规则（必须唯一且稳定）：**

```
docId = "D-" + {表名缩写} + "-" + {两位序号}
例：D-KGBSB-01、D-SGRZ-003
```

> 同一目录项内序号从 01 起；`docId` 与 `docNo` **解耦** —— 编号可被人工改，`docId` 永不改。

### 2.9 `_trash`（回收站索引）

```jsonc
"_trash": [
  {
    "trashId": "T-20260916-001",                        // 格式 T-YYYYMMDD-NNN
    "type": "doc",                                      // doc（单份）| item（整目录项）
    "itemId": "二-01",
    "docId": "D-KGBSB-02",                              // type=doc 时有
    "docNo": "YY123-KGBSB-02",
    "originPath": "二、过程分册/1、开工报审表/YY123-KGBSB-02_开工报审表.docx",
    "trashPath": "_回收站/T-20260916-001/YY123-KGBSB-02_开工报审表.docx",
    "deletedAt": "2026-09-16T15:10:00",
    "documents": [ ]                                    // type=item 时，其下所有文档的 {docId, docNo, originPath}
  }
]
```

**还原规则**：按 `originPath` 回原位 → 编号走 `restore()` 取回原号 → 若目标位置已被占用（同名同号），**提示用户改名，不静默覆盖**。

## 4. `填数规则.yaml` 正式规格

### 4.1 顶层结构

```yaml
version: "1.0"                    # 必填，变更时递增；工程里记 _generatedWith.ruleSetVersion
policies: { }                     # 全局策略（§4.2）
rules: [ ]                        # 规则列表（§4.3）
tables: { }                       # 子表数据源（§4.4）
counters: { }                     # 口径配置（§4.5）
```

### 4.2 `policies`（全局策略）

```yaml
policies:
  dateAutoFill: false             # bool, 日期是否自动填（固定 false，改 true 必须走变更记录）
  subtableMode: program-side      # enum: program-side | template-side（固定 program-side）

  manualFields:                   # S6 封闭集：引擎见到这些字段的规则必须报错拒绝
    fields:
      - startDate
      - endDate
      - creationDate
      - docDate
      - signDate
      - logDate
      - reviewTime
      - handoverTime
      - initialAcceptanceDate
      - acceptanceDate
      - trialRunStartDate
      - dataGovernanceDate
    tables:
      - expertScoreList           # 评分表由专家现场填
    patterns:                     # 字段名匹配则拒绝（正则）
      - "^expert.*"               # 专家签名/意见类
      - ".*Sign$"
```

**实现要求**：加载期若发现任何规则 `target` 命中 `manualFields` → **直接抛错退出（退出码 3）**，错误信息写清是哪条规则。

### 4.3 `rules[]`（规则）

每条规则**必须**有：`id` / `target` / `type` / `source` / `on`。`type` 只允许下面 9 种。

```yaml
rules:
  - id: proj.projectName
    target: projectName
    type: direct
    from: project.projectName
    source: S1
    on: [T1, T2]

  - id: fmt.contractAmount
    target: contractAmount
    type: format
    from: project.contractAmount
    transform: { num: true, decimals: 2, strip: true }
    source: S2
    on: [T1]

  - id: compose.buildSite
    target: buildSite
    type: compose
    parts: [project.buildSite]
    join: ""
    source: S2
    on: [T1]

  - id: agg.weeklyDone
    target: weeklyDone
    type: aggregate
    from:
      docs: { itemId: "二-10" }          # 源文档范围（按 itemId）
      dateWithin: week                    # week | month | range
      field: todayWork                    # 取哪个字段
    transform:
      dedup: true                         # 去重
      order: date                         # date | docNo | none
      join: "；"
    source: S4
    on: [T7]
    require: { minDocs: 1 }               # 前置：源文档不足则 fail
    fail: block                           # block（不生成）| warn（生成但标记）

  - id: agg.monthlyDone
    target: monthlyDone
    type: aggregate
    from: { docs: { itemId: "二-11" }, dateWithin: month, field: weeklyDone }
    transform: { dedup: true, order: date, join: "；" }
    source: S4
    on: [T7]
    require: { minDocs: 1 }
    fail: block

  - id: stat.weather
    target: weather
    type: statistic
    from: { docs: { itemId: "二-10" }, dateWithin: week, field: weather }
    transform: { mode: countDays, template: "{value} {n} 天", join: " / " }
    source: S4
    on: [T7]

  - id: stat.workerCount
    target: workerCount
    type: statistic
    from: { docs: { itemId: "二-10" }, dateWithin: week, field: workerCount }
    transform: { mode: avgAndPeak, numberTemplate: "平均 {avg} 人，最多 {peak} 人" }
    source: S4
    on: [T7]

  - id: cnt.trialRunBusiness
    target: trialRunBusinessCount
    type: count
    from: { docs: { itemId: "五-06" }, table: trialRunList }
    transform: { mode: rows, excludeEmpty: true }
    source: S4
    on: [T7]

  - id: ref.docNo
    target: docNo
    type: reference
    from: numbering.allocate(itemId)
    source: S0
    on: [T2, T3]
    bind: permanent                       # 一次分配永久绑定

  - id: cond.noContract
    type: condition
    when: { empty: project.contractNo }
    then: { "$docNo.prefix": "{abbr}" }
    else: { "$docNo.prefix": "{contractNo}-{abbr}" }
    source: S2
    on: [T1]

  - id: inherit.handoverPlace
    target: handoverPlace
    type: direct
    from: project.buildSite
    source: S2
    on: [T2]
    overridable: true                     # 允许文档级覆盖
```

### 4.4 九类规则的参数定义

| type | 必需字段 | 可选字段 | 语义 |
|---|---|---|---|
| `direct` | `from` | `overridable` | 直接取值。`from` 支持 `project.<key>` / `doc.<key>`（本份已有值） |
| `alias` | `from`（自然语言源）/ `candidates[]` | `confirm: true` | 从文本/上传件抽取（**必须人工确认**，落为 S5） |
| `format` | `from` / `transform` | `overridable` | 格式化。`transform` 支持 `num`（数字化）、`decimals`、`strip`（去空格）、`pad`、`prefix`、`suffix` |
| `compose` | `parts[]` / `join` | `skipEmpty: true` | 多段拼接，`parts` 元素同 `from` 语法 |
| `aggregate` | `from.docs` / `from.dateWithin` / `from.field` | `transform` / `require` / `fail` | 跨文档文本汇总（**周报月报核心**） |
| `statistic` | `from` / `transform.mode` | `transform.template` | 统计。`mode`: `countDays` / `avg` / `peak` / `avgAndPeak` / `sum` |
| `count` | `from.docs` / `transform.mode` | `transform.excludeEmpty` | 计数。`mode`: `rows`（行数）/ `docs`（文档数）/ `distinct`（去重值数） |
| `reference` | `from`（`numbering.*`） | `bind: permanent` | 引用系统生成值 |
| `condition` | `when` / `then` / `else` | — | 条件规则。`when` 支持 `empty` / `notEmpty` / `equals` / `in`；`then`/`else` 的键可用 `$<字段>.<属性>` 语法 |

**`from.docs` 支持的匹配键（三选一）**：`itemId`（推荐）/ `volume`（整个分册）/ `tag`（自定义标签）。

**`dateWithin` 取值**：`week`（上一自然周，周一至周日）/ `month`（上一自然月）/ `range`（配合 `from`/`to`）。

**禁止**：`rules[].from.docs` 不得引用 `manualFields` 里的字段（加载期校验）。

### 4.5 `counters`（口径配置）

```yaml
counters:
  weeklyWorkerCount: avgAndPeak      # avg | peak | avgAndPeak（默认 avgAndPeak）
  logDedup: true                     # 日志文本是否去重合并
  weatherFormat: countDays           # countDays | listAll
  trialRunUserCount: manual          # manual | distinct（默认 manual，二期再自动）
  trialRunBusinessCount: manual
```

## 5. 字段锚点规格（ADR-9）

### 5.1 写入格式

填充一个占位符时，**同时写三样**：

```
① 正文（可见）
   岳阳市财政局业务系统信息化建设项目

② 书签包裹（可定位，Word 中默认隐藏）
   <w:bookmarkStart w:id="9001" w:name="yz_projectName"/>
   岳阳市财政局业务系统信息化建设项目
   <w:bookmarkEnd w:id="9001"/>

③ customXml 台账（不污染正文）
   word/customXml/item1.xml:
   { "yz_projectName": { "value": "…", "source": "S1", "ruleId": "proj.projectName", "at": "…" } }
```

### 5.2 硬规则

| 项 | 规定 |
|---|---|
| 书签名前缀 | 一律 `yz_` + 字段 key（如 `yz_projectName`） |
| 书签 id | 从 **9000** 起顺延；生成前查重，避开模板已有 id |
| 只认自己的 | 模板里已有的其他书签**一律不动**（不删、不改、不重命名） |
| 锚点开关 | `fill --anchor off` 时不写锚点（用于纯填充场景） |
| 锚点丢失 | 保存时检测到锚点缺失 → 该字段降级为普通文本，**不报错**，只在 UI 提示"该字段已脱离自动同步" |
| customXml 部件 | 每个 docx 一个 `item1.xml`；不存在则创建（含 `[Content_Types].xml` 与 `_rels` 注册） |

### 5.3 变更检测口径（半自动同步用）

保存文档时，对每个 `yz_` 锚点：

```
锚点值 ≠ 档案值  →  列为「改动候选」
   ├─ 用户选「仅本份」 → 写 _documents[路径][key]，来源记 S3
   ├─ 用户选「同步全册」 → 改项目级值 + _fieldSources 记 S1/manual，提示"另有 N 份包含该字段，是否一并更新"
   └─ 用户选「撤销」 → 回写锚点值
```

## 6. 契约 JSON 与退出码

### 6.1 统一返回结构（所有引擎 `--json` 时 stdout 最后一行）

```jsonc
{
  "ok": true,                                    // bool, 业务是否成功
  "engine": "fill",                              // string, 引擎标识
  "summary": "37 份 / 171 处已填充 / 0 处残留",    // string, 一句话结论
  "stats": { "docs": 37, "filled": 171, "missing": 0, "residual": 0 },
  "items": [ ],                                  // array, 明细（按需）
  "errors": [
    { "file": "二、过程分册/…docx", "part": "document", "key": "projectGoal",
      "reason": "缺值·保留占位符", "level": "warn" }
  ]
}
```

**`errors[].level`**：`block`（阻断导出）/ `warn`（提示）。

### 6.2 退出码

| 码 | 含义 | 典型场景 |
|---|---|---|
| `0` | 成功 | 全部完成 |
| `1` | 业务失败 | 校验不通过、前置条件不满足（如无日志生周报） |
| `2` | 参数错误 | 必填参数缺失、枚举值非法、路径不存在 |
| `3` | 环境错误 | 缺依赖（lxml）、模板缺失、规则文件语法错误、命中 S6 封闭集 |

### 6.3 进度输出（不破坏契约）

stdout 可穿插 `#PROGRESS <done>/<total> <描述>`，工具层与壳忽略这些行，**只解析最后一行**。

## 7. 校验规则口径（verify）

| 检查项 | 判定 | 级别 |
|---|---|---|
| 残留占位符 | 文本含 `{{xxx}}` 且 `xxx` 是**启用字段** key | `block` |
| 未定义 key | 文本含 `{{xxx}}` 但 `xxx` **不在字典**（含停用/归档字段） | `block` |
| 必填缺失 | `projectName`/`ownerUnit`/`constructionUnit` 为空；或 `contractNo` 有条件但为空 | `block` |
| 文档缺失 | `_docs` 里有记录但磁盘文件不存在 | `block` |
| 编号断号 | 同 `itemId` 内 `allocated` 序号不连续**且非 tails**（允许中间留坑） | `warn` |
| 编号重复 | 同一 `docId` 对应多个编号，或同 `itemId` 内两个 `docId` 同号 | `block` |
| 单位名不一致 | 同一字段在不同文档中的值不相等（如 `constructionUnit`） | `warn` |
| 金额不符 | `contractAmount` 与 `_assets.devices` 总价合计偏差 > 1% | `warn` |
| 日期被误填 | 模板日期留白位置出现数字（人工手写属正常，**仅在自动生成后立即检测**） | `warn` |
| 文件损坏 | 无法作为 zip 打开 | `block` |

**不算问题（明确豁免）：**
- 日期留白（`年　　月　　日`、`日　期：`）
- 正文自然语言里的 `XX`、`×××`、`___`
- 签字/盖章/意见栏留白
- 固定文案（质保期承诺书正文等）

## 8. 版本与迁移

| 对象 | 版本字段 | 迁移规则 |
|---|---|---|
| `project.json` | `_schema: "yzproj/1.0"` | 主版本变更时提供 `migrate_<from>_to_<to>.py`；打开旧工程时自动备份后迁移 |
| 字段字典 | `version` | 新增字段向后兼容；删除字段进 `removedFields` 归档（**不物理删**） |
| 填数规则 | `version` | 规则变更后旧工程仍可复现（`_generatedWith.ruleSetVersion` 记录了生成时用的版本） |
| 引擎 CLI | 语义化 | 冻结后只加参数，不改已有参数语义 |
| 模板资产 | 目录快照的 `sourceHash` | 模板/清单变更 → 刷新快照时对比，**提示差异由用户决定是否应用** |
