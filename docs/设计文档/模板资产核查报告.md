### 9.0 ⚠️ 先撤回一条我自己造的假事故（本报告最重要的一节）

**我一度报出「6 份模板段前分页失控，每段强制新起一页，会打成 15–21 页废纸」，并已写好批量删除工具、工头也已批准动手 —— 复核时发现：这个结论是错的。**

**错在哪**：`w:pageBreakBefore` 是 OOXML 的 **on/off 类元素**，必须读 `w:val`：

```xml
<w:pageBreakBefore/>            → 启用（缺省 val 视为 true）
<w:pageBreakBefore w:val="1"/>  → 启用
<w:pageBreakBefore w:val="0"/>  → ★ 关闭！★
```

本包这 199 处的**实际形态全是 `<w:pageBreakBefore w:val="0"/>`** —— 它们是「**显式关闭段前分页**」，是 Word 另存/复制时固化格式的正常产物。

**我的 `audit_typography.py` 初版没读 `w:val`，把"存在"当成了"启用"。**

**复核实测（全包 37 份）**：

```
全包合计：真启用 0 处 / 显式关闭（w:val="0"）199 处
真启用段前分页的模板：0 份
```

**差点造成的后果**：`fix_typography.py` 会删掉这 199 处 `w:val="0"` 元素 —— 虽然它们无害，但**删了毫无必要，且是对冻结模板的无谓改动**。安全网在预演阶段就拦住了（真启用 0 处 → 拒绝动手）。

**已做的处置**：
1. `audit_typography.py` 增加 `is_on(el)` 判定，**只认真启用**；脚本头注释写死这条纪律
